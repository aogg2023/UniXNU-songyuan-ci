## 解读

- `esr = 0x9600004f`：EC=0x25（同 EL 数据中止）、WnR=1（写）、DFSC=0b001111（L3 权限错）。
- `far` 落在中断栈保护页里，`sp = 0xfffffff008643e28` 在保护页上方不远处 —— 异常栈被压到保护页，
  一次写栈触发权限错。
- panic 的 caller 是同步异常向量 `sleh_synchronous_sp1`，pc 在 `vm_fault_internal` 内部 ——
  即「缺页处理过程中再次异常」，`check_exception_stack` 判 SP 非法后抛出这条二次 panic。
- **屏幕上的这句话永远是二次现场**；第一次缺页的 FAR/ELR 还在异常帧里，没打出来。

## 为什么不自动重启

`debug=0xc` = `DB_NMI(0x4) | DB_KPRT(0x8)`，没有 `DB_REBOOT_ALWAYS(0x100000)`。
`osfmk/kern/debug.c` 里只有

```c
if (debug_boot_arg & DB_REBOOT_ALWAYS) {
        kdp_machine_reboot_type(kPEPanicRestartCPU, debugger_panic_options);
}
```

才会走复位，否则 `halt_all_cpus(TRUE)` 停住自旋；此刻看门狗也没接管，所以只能长按电源。

- 想自动回 Android：`debug=0x10000c`（代价：屏幕闪一下就复位，来不及拍照）
- 想留屏拍照：保持 `debug=0xc`，手动长按电源

`handshake structure not initialized` 是 panic 后与 iBoot 调试握手失败，噪音。

## 异常环（0211）拿到的第一手数据

加了 `sleh_synchronous` 入口的 8 条环之后，屏幕显示 9 次同步异常、后 8 次**完全相同**：

```
SWEET EXC 1..8: esr=0x96000005 far=0x9e pc=0xfffffff007359ff4
                lr=0xfffffff007359ef0 sp=0xfffffff008647xxx fp=0xfffffff008647a60
```

- `esr=0x96000005`：EC=0x25 数据中止、**读**、DFSC=0b000101（L1 翻译错）
- `pc` 符号化 = `_vm_fault_internal+0x6c`，反汇编正好是：

```asm
fffffff007359ff4:   ldrb   w8, [x0, #0x9e]      ; x0 = map == NULL
```

- `lr` = `_vm_fault$XNU_INTERNAL+0x14`（包装层调用 internal）

即：**`vm_fault_internal(NULL, …)` → 读 `[0+0x9e]` 缺页 → 异常处理里又用同一个 NULL map 调 `vm_fault` → 无限递归**，每次吃掉一点异常栈，直到压到 `_intstack_low_guard` 触发二次 panic。

## 第二轮：NULL map 从哪来

1. 在 `handle_user_abort` 加了 `map == NULL` 守卫（0212）→ **没触发**，panic 与之前一字不差。
   说明不是用户态异常那条路进来的。
2. 静态分析：整个内核里 `bl _vm_fault$XNU_INTERNAL` 只有 **12 个调用点**：

| 次数 | 调用者 |
|---:|---|
| 7 | `_exec_prefault_data`（exec 预缺页） |
| 1 | `_handle_user_abort`（已加守卫） |
| 1 | `_sleh_synchronous`（内核 abort，`recover != 0` 时用 `thread->map`） |
| 1 | `_vm_map_get_phys_page` |
| 1 | `_vm_test_per_mapping_internal_accounting`（测试） |
| 1 | `IOMemoryDescriptor::populateDevicePager` |

3. `_current_map` 反汇编 = `current_thread()->map`（`ldr x0,[x0,#0x490]`），
   而 `thread_create` 里是 `new_thread->map = parent_task->map`。
   → **`thread->map` 为 NULL**，即某个线程的地址空间没建立起来。

## 第三轮：守卫挪到 `vm_fault_internal` 入口（0213）

```c
if (__improbable(map == NULL)) {
        panic("SONGYUAN: vm_fault_internal map=NULL vaddr=%p caller=%p",
            (void *)vaddr, __builtin_return_address(0));
}
```

等真机拍屏拿到 `caller=` 后，符号化即可确定是 exec 预缺页、内核 abort 恢复路径，还是 IOKit 的 pageable 描述符。
